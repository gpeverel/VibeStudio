# Этап 2: граничные сценарии Git

Источник: `docs/SPEC.md`, разделы «Git-логика» и «Этап 2».
Исполняемый файл: `tests/spec-boundaries.test.ts`, Vitest.
Команда после настройки общего раннера: `npm test -- tests/spec-boundaries.test.ts`.

Каждый тест создаёт настоящий временный репозиторий внутри `.tmp/`, затем удаляет свой каталог.
Удалённый репозиторий в push-тестах — локальный bare-репозиторий; сетевые сервисы не нужны.
Репозитории с пробелами в путях используются во всех сценариях.

| ID | Что проверяем | Вход | Ожидаемый результат |
|---|---|---|---|
| S2-B01 | Нет Git и нет подтверждения инициализации | Каталог с пользовательским файлом, без `.git` | `not_git_repository`; `.git` не создаётся, файл сохранён |
| S2-B02 | Требуется минимум один коммит | Репозиторий после `git init` | `no_commits`; worktree и ветка сессии не созданы |
| S2-B03 | Изоляция грязного старта | Staged, unstaged и untracked изменения | Предупреждение `dirty_tree`; worktree от HEAD; локальные изменения и индекс основной копии сохранены |
| S2-B04/staged | Блокировка применения | Изменение в индексе основной копии | `dirty_tree` с именем файла; HEAD, индекс, diff и файлы не меняются |
| S2-B04/unstaged | Блокировка применения | Изменённый отслеживаемый файл | Тот же отказ с именем файла, основная копия сохранена |
| S2-B04/untracked | Блокировка применения | Новый неотслеживаемый файл | Тот же отказ с именем файла, новый файл сохранён |
| S2-B05 | Старт с detached HEAD | Основная копия отсоединена от ветки, база — SHA | Worktree от SHA, режим `keep_branch`, основная копия остаётся detached |
| S2-B06 | Недоступность применения с detached HEAD | Готовая ветка сессии и detached основная копия | `detached_head`; основная копия и ветка сессии сохранены |
| S2-B07 | Исчезновение базовой ветки | После создания worktree базовая ветка удалена | `base_branch_missing`; другая ветка не выбирается автоматически, изменения сессии сохранены |
| S2-B08 | Восстановление remote-ветки | Ранее опубликованная ветка удалена в bare remote | Обычный push создаёт ветку с HEAD сессии |
| S2-B09 | Запрет force-push | Ветки сессии и remote разошлись | `non_fast_forward`; оба HEAD сохранены |
| S2-B10 | Предупреждение о подмодулях | Репозиторий с настоящим локальным подмодулем | `submodules_unsupported`, основная копия не меняется |
| S2-B11 | Предупреждение о LFS | Закоммиченный LFS filter в `.gitattributes` | `lfs_unsupported`, основная копия не меняется |
| S2-B12 | Место разрешения конфликта | База и сессия изменили одну строку по-разному | `merge_conflict`; конфликт в worktree; HEAD и файлы основной копии сохранены |

## Контракт и границы проверки

`tests/contracts/git-boundaries.ts` фиксирует предлагаемые имена методов, ошибок и полей результата.
Спецификация задаёт поведение, но не эти имена; при реализации API контракт можно согласованно переименовать.
Ожидается экспорт `createGitAdapter()` из `src/adapters/git/index.ts`.
UI-предупреждения, выбор другой цели и подтверждение `git init` здесь не проверяются: проверяется результат адаптера для будущего UI.
LFS проверяется по атрибутам, без скачивания LFS-объектов и установки расширения.

При отсутствии адаптера каждый тест падает на assertion с меткой `RED_MISSING_IMPLEMENTATION`.
Это подтверждает отсутствие реализации, но ещё не выполнение поведенческих assertions: они выполнятся после появления адаптера.
Ошибки подготовки Git-репозитория, импорта, раннера или типов следует учитывать отдельно от ожидаемого RED.
