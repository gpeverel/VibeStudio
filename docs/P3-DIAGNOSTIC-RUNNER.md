Расход завершённых наборов указан выше; описанная команда не означает разрешения нового запуска. Другой движок для обхода ограничений не запускается.

Сценарий создаёт собственный пустой cwd в системном tmp и выполняет строго по одному вызову: `--version`, `--help`, `exec --help`, `exec resume --help`, `login --help`, `login status`. Prompt отсутствует, stdin пуст, модельных вызовов **0**. Аргументы передаются массивом; shell для этих команд не используется. Первое несоответствие интерфейса, ошибка, превышение лимита, Stop или отказ записи evidence прекращает набор. Последующие пункты остаются `not_run`; повторов нет.

Перед первым вызовом фиксируются realpath, stat и SHA-256 wrapper, native executable и Node. Перед каждым вызовом повторно сверяются realpath/stat, включая mode, и соответствие Node в передаваемом PATH. PATH не переписывается. Смена установки/файла прекращает набор. SHA-256 снимается до исполнения; stat-recheck не является криптографической проверкой каждого запуска и не устраняет окно до spawn.

Бюджеты: максимум 6 диагностических попыток; 5 с на процесс, 200 мс мягкой остановки, 1 с drain. CLI-обёртка имеет общий watchdog 45 с, затем до 5 с на остановку и завершение. Это таймер в процессе стенда, не отдельный ОС-supervisor; зависание самого JS event loop им не покрывается. ProcessRunner управляет собственными группами. Сигнал, `done` или ESRCH сами по себе не доказывают exit/EOF; detached-потомки не гарантируются.

stdout/stderr ограничены отдельно по 64 КиБ. Превышение останавливает процесс. Необходимы успешный код, EOF обоих потоков, settled и отсутствие completion issues. `login status` различает authenticated / unauthenticated / unknown; его результат не подтверждает запрос к модели или обновление авторизации. Ограничение справки resume проверяется отдельно от первого хода.

Окружение пропускается через существующий Codex allowlist. HOME, CODEX_HOME и штатная авторизация сохраняются, их значения не выводятся. Credentials, конфигурация и hooks не читаются и не изменяются. Модельных расходов нет; отсутствие сети/служебных записей самой CLI не обещается. CLI может обращаться к штатному auth backend и писать свои журналы/кеши.

## Evidence и cleanup

В отдельном собственном tmp-каталоге `vibestudio-codex-D-evidence-*` создаётся `report.json` с mode 0600. Checkpoint записывается до первого probe, после каждого завершённого probe и после cleanup. Сводка содержит provenance, идентичности файлов, бюджет, число попыток, известные имена флагов, версию, auth verdict, code/exit/EOF/signals/issues, длительности и состояние cleanup. Сырые stdout/stderr, тексты ошибок и значения env не сохраняются. Version/help подтверждают только объявленный интерфейс.

Путь evidence выдаётся в итоговой строке stdout. Evidence-каталог сохраняется для ревью; в репозиторий автоматически ничего не экспортируется. Рабочий cwd удаляется только после подтверждённых exit и EOF всех запущенных диагностик. При неподтверждённом завершении он сохраняется с причиной; последующее удаление возможно только после подтверждения прекращения собственного запуска.

При аварийном срабатывании watchdog итог — `unconfirmed`, exit 1. Последний checkpoint может быть неполным: точное число вызовов неизвестно, верхняя граница — 6. Остаток разрешения не восстанавливается по неполному checkpoint; без нового решения повтор запрещён. Обезличенное evidence не подтверждает отсутствие ранних эффектов расширений и не выдаёт production-ready.

## Продолжение после независимого ревью 2026-10-20

Отдельный GPT-рецензент `review_p3_d` выполнил чтение стенда и репродукцию lifecycle в памяти, без реальной CLI. Это новое независимое ревью, не отзыв прежних участников B/C. Найдены и исправлены два дефекта:

1. `Promise.all(stops)` мог не дождаться kill, добавленного после deadline во время ожидания interrupt. Теперь ожидание повторно учитывает все новые запросы Stop, включая поздний отказ kill. Срок ожидания конечен, ошибка EPERM сохраняется в результате.
2. Проверка Node раньше отбрасывала относительные и пустые компоненты PATH, хотя `/usr/bin/env node` их учитывает. Теперь такой PATH отклоняется до spawn без переписывания окружения. Корректный абсолютный PATH остаётся неизменным.

До исправления новые отрицательные регрессии дали **22 passed / 4 failed**. После исправления добавлена также положительная проверка абсолютного PATH. Повторное независимое ревью не нашло блокирующих замечаний в проверенной области; прежняя репродукция теперь дожидается kill и сохраняет `signal_failed/kill/EPERM`.
