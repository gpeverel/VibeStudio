# P2b: отдельный сценарий practical live-приёмки

Дата подготовки: 2026-10-13. Владелец стенда и отчёта — C. **Это предложение для отдельного разрешения, не разрешение и не результат живого прогона.** Во время инженерной работы P2b настоящие Claude/Codex, auth/model-пробы и этот стенд не запускаются.

## Условие запуска

Стенд `tests/live/claude-practical.live.ts` использует `createClaudeAdapter` с production-оценкой, без synthetic `assessPractical`, фиктивного verifier, изменения HOME, копирования токенов или расширения argv. Он отдельный от исторического strict-стенда. Неподтверждённая effective managed-политика блокирует prompt. Недостающий интерфейс CLI нельзя заменить отсутствующим файлом, текущим init или согласием с ограничением.

Для установленной комбинации пока не подтверждён источник полной effective-политики. Поэтому возможный фактический результат предложенной команды — конкретный предпусковой отказ, **ноль модельных запусков** и незакрытая приёмка. Перед разрешением исполнитель сверяет реализацию сборщика данных и нижеуказанный бюджет; при изменении команд/числа диагностик сценарий сначала обновляется.

После отдельного разрешения — ровно одна команда, с явным выбором нового файла:

```sh
LIVE=1 PRACTICAL_LIVE=1 CLAUDE_BIN=/opt/homebrew/bin/claude sh scripts/with-node.sh npm exec --offline --no -- vitest run --config vitest.live.config.ts tests/live/claude-practical.live.ts
```

Оба флага — технический барьер от случайного запуска, не подтверждение разрешения. `npm run test:live` без фильтра **не используется**, чтобы не выбрать исторические пробы. `retry: 0`, `bail: 1`, один worker, последовательное выполнение. При первом отказе остальные пробы не выполняются; автоматических повторов и fallback на прямой runner нет.

## Конечный бюджет и проверяемые факты

Предлагается максимум **пять модельных запусков** production-адаптера. Перед каждым `start` штатный detect выполняет не более трёх немодельных диагностик: `--version`, `--help`, `--safe-mode --restricted auth status`; суммарно не более **15 диагностик**. Дополнительных ручных auth/version/config-проб нет. Внутренние запросы CLI к провайдеру этим числом не ограничены; денежный потолок и принудительное provider refresh не обещаются.

| Проба | Запрос и наблюдение | Условие приёмки |
|---|---|---|
| `p-read` | Без persistence: прочитать собственный README, найти файл Glob и случайную строку Grep; один раз запросить Write собственного `write-control.txt`, без обходов и повторов | Наблюдены Read/Glob/Grep и `permission_denied` для Write; ответ содержит контрольную строку; исходный контроль не изменён; transcript собственного UUID отсутствует; result согласован с exit/EOF |
| `p-persist` | Новый UUID с persistence: запомнить случайную метку, не записанную в проект; вывести метку режима по текущей системной инструкции | Есть transcript только своего UUID и первый режим; без чтения чужих transcripts |
| `p-resume` | Тот же UUID и новый turnId, метка повторно не передаётся; определить режим по текущей системной инструкции | Восстановлена метка; отличимый ответ для продолжения; builder передал отличающуюся инструкцию и `--system-prompt-snapshot off` |
| `p-extensions` | Собственный проект содержит hook/MCP/plugin-приманки; запрашивается обычное чтение | Production-допуск, известный ожидаемый inventory и фактический init согласованы; нет marker исполнения и расширения tools; неизвестная распознаваемость приманки не становится доказанным отключением |
| `p-stop` | Собственное чтение; Stop после `run_started`, до terminal | `stopAccepted=true`, interrupted, один terminal; подтверждённый exit/потоки либо конкретные ошибки completion; отсутствие detached-потомков не заявляется |

Первые три пробы нужны только для новой production-комбинации: исторические 01–03 подтверждали builder → runner → parser другого стенда и не заменяют её проверку. Историческая 04 со script/safeguards **не повторяется**. Не просим модель обходить safeguards или выполнять attack-script. Отказ провайдера или safeguards останавливает набор.

Запрос Write в `p-read` ограничен собственным безвредным контрольным файлом и входит в тот же единственный модельный вызов. Для отрицательного права требуется нормализованное событие отказа CLI и отсутствие эффекта. Если исключённый из `--tools` Write не порождает `permission_denied`, либо модель отвечает отказом только в прозе, стенд не засчитывает проверку; права не расширяются ради получения события. Одно отсутствие вызова Write не считается подтверждением. Наличие transcript проверяется только для заранее созданного собственного UUID до и после запуска без persistence.

Изменение системной инструкции проверяется существующим различием first/resume в `buildAgentInstructions`; продуктовый сборщик инструкций не меняется. Отличимый ответ — наблюдение поведения, а не доказательство того, что модель не могла угадать режим по истории. Стенд сохраняет `instructionApplication: unconfirmed` даже при совпавшем слове: самостоятельное применение новой инструкции требует отдельной оценки фактических данных. Если наблюдение неоднозначно, критерий остаётся незакрытым; одна разница argv недостаточна.

Для каждой модели: timeout 90 с, stop grace 2 с, drain 2 с; общий внешний предел теста 110 с. Одна диагностика: timeout 5 с, stop grace 0,1 с, drain 0,5 с. При неопределённом завершении новый запуск запрещён стендом. Parser: строка до 1 MiB, состояние до 2 MiB, 1024 записи; диагностический бюджет адаптера 16 KiB. Ограничиваются буферы стенда, а не RSS CLI средствами ОС.

## Каталоги, побочные записи и уборка

Стенд создаёт только собственный `os.tmpdir()/vs-practical-live-*`, с `project/`, контрольными файлами и marker-каталогом. Искусственные приманки могут записывать только в этот marker-каталог; не создают бесконечных процессов или отделённых потомков. Проектные настройки не подаются через `--settings`, plugin не добавляется через `--plugin-dir`, права не расширяются. Конфигурация приманки входит в новое предпусковое решение; прежний положительный допуск не переиспользуется.

HOME, Keychain и штатные helpers остаются исходными. Ожидаются обычные CLI/auth-записи в штатном каталоге состояния (обычно `~/.claude`, либо уже заданный `CLAUDE_CONFIG_DIR`), в том числе transcripts сохраняемой собственной сессии и возможные служебные журналы/cache. Даже немодельный auth status может создавать записи. Чужие transcripts не читаются и не удаляются; собственные transcripts также не удаляются автоматически. Наличие API-key/env-token не подменяется другим входом ради успеха.

В `finally`/teardown стенд останавливает только сохранённые собственные `AgentRun`/`ProcessRun`, дожидается конечного completion и удаляет собственный временный проект. PID/строка команды не используются для поиска чужих процессов. Ошибка Stop не стирается очисткой. Неизменность контроля проверяется до удаления даже при неуспешном assertion; подменённые симлинки не разыменовываются уборкой. Полного tree-kill нет.

Безопасные результаты записываются в отдельный `os.tmpdir()/vs-practical-evidence-*`, который сохраняется для проверки. Не сохраняются raw stdout/stderr, credentials, содержимое auth status, конфигурационные дампы или значения env. Отчёт содержит наблюдённые исходы, completion, имена инструментов из закрытого набора, результаты сравнения контроля и число запусков. Строки модели и пути из CLI не публикуются без ручной проверки.

## Граница доказательств

Локальный auth status подтверждает только свою диагностику; успешный provider request — конкретный запрос. Provider refresh без фактического наблюдения остаётся **неизвестным**. Отказ auth/provider обрабатывается типизированной ошибкой, без смены credentials и без автоматического повторения запроса.

Неизменные marker-файлы не доказывают отсутствие всех hooks; регистрация plugin не доказывает исполнение; отсутствие tool events не доказывает отключение. Поздний отказ на init не отменяет возможный ранний hook. Свойства read-only не являются файловой или сетевой ОС-изоляцией.

Новые реальные fixtures создаются только после отдельного разрешённого фактического прогона и проверки секретов, с версией CLI, точными безопасными argv, контекстом, происхождением и ограничениями. Этот стенд сам не создаёт fixtures и не маркирует synthetic-данные как реальные. Старые `tests/fixtures/claude/real/01–04` сохраняются без правок. До принятой live-приёмки **P2b и весь 0C не закрыты**.
