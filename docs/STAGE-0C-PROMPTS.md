# Инструкции 0C: происхождение и адаптации

Дата: 2026-10-09. Реализация: `src/core/agent-instructions.ts`.

## Контракт

`buildAgentInstructions({ resume: boolean }): string` — чистая функция без зависимостей, файловой системы и переменных окружения. Возвращает только дополнительные инструкции. Пользовательский `prompt` не принимает и не изменяет. Вызов и передача инструкций принадлежат Claude-адаптеру; большой пользовательский запрос передаётся через stdin. Сборщик не создаёт сессию, не проверяет наличие транскрипта и не восстанавливает процесс.

Первый ход и resume различаются первой фразой. Продолжение не утверждает причину завершения прошлого хода, наличие полного контекста или точное повторение отвергнутого действия. Для доступа по-прежнему требуется проверенный профиль адаптера: текст инструкции не обеспечивает ограничение инструментов, файлов или сети.

## Передача и пределы проверки

Для отдельных дополнительных инструкций предусмотрен `--append-system-prompt`; пользовательский запрос остаётся в stdin. В CLI 2.1.295 локальный `--help` описывает сохранение system prompt между ходами. При изменении инструкции на resume нужен `--system-prompt-snapshot off`, иначе CLI может продолжать использовать первоначальный текст. Это также описано в [официальной CLI reference](https://code.claude.com/docs/en/cli-reference#system-prompt-flags). Наличие и комбинацию флагов проверяет адаптер; фактическое применение на resume проверяется живой пробой, а не строковым тестом.

Исследовательские обозначения, исходные выражения, описания происхождения и неподтверждённые гарантии не попадают в возвращаемую строку. Отчёт хранится отдельно от неё. Автоматические проверки сборщика принадлежат тестовому набору B; они не доказывают выполнение инструкций моделью. Живая проверка передачи инструкций и продолжения диалога до разрешённой пробы остаётся незакрытой.

### Фактическая проба 2026-10-10

Первые три живые пробы прошли с производственными инструкциями и `--system-prompt-snapshot off`: первый ход, сохранение и resume с меткой, не переданной повторно. Это подтверждает продолжение контекста и совместимость argv для этих ходов. Фактическая замена system prompt на resume отдельно не доказана: ответ меткой не различает первую и последующую вводную. Тексты инструкций в этом продолжении не менялись; приёмка обеспеченной изоляции остаётся открытой.

### Методика отдельной practical-приёмки — 2026-10-17

До первого practical-модельного запуска заменён недискриминирующий критерий «слово ПРОДОЛЖЕНИЕ»: он мог быть выведен из истории. Новый сценарий запрашивает ровно две строки: `КОНТЕКСТ: <полный первый абзац добавленной инструкции VibeStudio>` и `МЕТКА: <сохранённая метка>`. Ожидаемые абзацы не включаются в пользовательские prompts или файлы проекта. В p-persist требуется дословный первый контекст, в p-resume — дословный новый контекст, отсутствующий в корректном первом ответе. Память случайной метки и фактические argv проверяются отдельно. Пересказ, одно слово, первое предложение вместо полного абзаца, оба абзаца или отказ дают required unconfirmed; точный противоположный контекст — failed. Любой из этих исходов останавливает набор.

Сборщик `buildAgentInstructions({ resume })`, его API и производственные формулировки не менялись. A и C повторно прочитали указатель `prompts/README.md`, соответствующие части `REPORT.md` и прежние источники `worker-first-task.md` (su, байты 1882162–1882269), `session-followup.md` (ep, 14797821–14798342), `shared-language.md` ($te, 1720344–1720500). Сохраняется адаптация из таблицы выше. Формат из двух строк — специфический запрос приёмки, которого нет в исходных шаблонах; правила приложения и механизм VibeForge не копировались.

Успех означает наблюдаемое использование полного актуального контекста **в конкретном ответе**. Статический текст теоретически можно угадать; криптографическая аттестация, полное извлечение скрытых инструкций и соблюдение всех будущих инструкций не заявляются. Raw-ответ и предыдущий текст используются только в памяти стенда; evidence содержит verdict. Синтетические регрессии и независимое ревью проверяют методику, не применение инструкции настоящей моделью. Реальный результат ещё предстоит получить отдельно.
