# 0C: обеспеченный профиль — исследование 2026-10-10

> Актуальное продолжение: [STAGE-0C-NATIVE.md](STAGE-0C-NATIVE.md). Native выбран пользователем; причина --help установлена (ICU), broker/launcher проверены немодельно, setsid stop-контрпример сохраняет блокировку. Нижеследующий текст — исходное исследование, не последний статус.


Работа одним агентом. Это решение по результатам исследования, **не подтверждение изоляции**. Новых модельных вызовов: **0**; один немодельный запуск CLI с --help в ограниченной лаборатории. Старый live-runner не запускался. Проба 04 не повторялась; обход safeguards не предпринимался. Четыре реальные fixtures, их metadata и подтверждённые первый ход/сохранение/resume сохранены.

## Матрица требований и механизмов

Нормативная база: SPEC §2–4, §10, §12–13. «Сейчас» ниже относится к производственному запуску через наш ProcessRunner, а не к внешней песочнице Codex и не к лабораторному профилю.

| Граница | Что должно обеспечивать | Что обеспечивает сейчас | Какого доказательства нет |
|---|---|---|---|
| `readRoots` | ОС-ограничение содержимого файлов всего CLI/потомков по разрешённым корням, с обработкой alias/inode; явные системные/auth/runtime исключения; правило инструментов чтения как дополнительная линия | Проверка структуры профиля: один корень равен cwd; Read/Glob/Grep. Пути не передаются ОС | Нет обеспечивающего launcher. Внешний прямой путь, симлинк и hardlink не закрыты в production. Нет утверждённого перечня служебного чтения |
| `runtimeWriteRoots` | ОС разрешает только точные служебные области, защищает их inode/предков и запрещает пересечение с пользовательскими файлами | Лексическая проверка пересечений, без realpath и ограничения spawn. Live-профиль содержит пустой список, хотя штатная CLI писала вне tmp | Нет списка фактических state/cache/refresh/transcript операций со штатной авторизацией и проверки алиасов. Нельзя выдать этот старый профиль за обеспеченный |
| `protectedPaths` | Запрет мутаций содержимого и метаданных по всем алиасам; защита от rename/remove предков, symlink и hardlink | Поле проверяется как абсолютные пути. Контрольные снимки ловят изменения после пробы | Нет запрета ОС. Снимок — детектор последствий, а не предотвращение; path-only лаборатория пропустила hardlink |
| `gitCommonDir` | Отдельный запрет записи реального common-dir, refs/config/index/objects/worktrees и алиасов независимо от cwd; без запуска hooks при диагностиках | Поле профиля + тестовый снимок Git; production spawn не ограничен | Нет ОС-защиты common-dir; worktree использует Git-ресурс вне своего корня. В VM допустим только собственный Git-репозиторий, а не writable mount общего Git |
| Сеть `provider-only` | Прямые IPv4/IPv6/UDP/Unix/Mach обходы закрыты; доступ только через доверенный broker с фиксированным перечнем provider-host/портов; проверка DNS/IP, redirects и жизненного цикла broker | Enum, запрет WebFetch/WebSearch, scrub env, выключение необязательного трафика. Это не сетевой firewall | Нет broker/политики DNS/OS launcher. HTTPS_PROXY сейчас удаляется builder. Проверен только kernel-запрет другого localhost-порта, не доменная политика и не Claude |
| Managed-конфигурация | Сверка эффективных file/drop-in/MDM/server/host/helper источников до разрешения эффектов; неизменная политика либо её изменение инвалидирует запуск; конфликт с обязательной границей даёт отказ | Managed-политика сохраняется safe-mode, но не исследуется adapter | Нет безопасной машинной аттестации эффективной политики; отсутствие одного файла недостаточно; runtime-доставка и исполняемый policyHelper тоже должны учитываться |
| Hooks и прочие helpers | Конфигурационная недоступность всех запрещённых источников + внешняя граница всего CLI и детей; managed-hook не может получить полномочия вне профиля | restricted/safe-mode/пустой setting-sources. Документация сохраняет часть managed-команд | Нет доказательства отсутствия исполнения до init. Пустой toolset модели не запрещает SessionStart/config helpers |
| MCP | Пустая эффективная конфигурация; прямые подключения/stdio процессы запрещённых серверов не запускаются; внешний launcher защищает возможные helper-процессы | strict-mcp-config + пустой mcpServers; реальные init MCP пусты | Реальные 06 не выполнялись; init не доказывает отсутствие запуска/соединения до его выдачи или во всех конфигурациях |
| Plugins/mods/skills | Запрет загрузки запрещённых компонентов и их handlers, сохранение строгого требования пустого init.plugins; предзапусковая конфигурация плюс внешний launcher | safe-mode не отключает builtin mods; в четырёх fixtures зарегистрированы два builtin plugin, skills и slash_commands пусты | Нет доказанного отключения builtin и эффективной managed-политики. Регистрация и исполнение различны; факт регистрации уже не удовлетворяет пустому списку |
| Остановка | Идентичность и завершение всех принадлежащих запуску процессов, включая сменивших сессию/группу; наследование ограничений и защита от делегирования внешнему supervisor | SIGTERM → SIGKILL своей POSIX-группе, ограниченное дренирование/таймауты | setsid/detached выходит из группы; sandbox не является средством удаления дерева. Crash/restart-принадлежность относится к этапу 1 и здесь не реализуется |

Профиль описывает агентские корни чтения, но не отдельные доверенные системные/auth-корни. Целиком запретить чтение вне cwd нельзя: бинарнику нужны runtime-библиотеки и штатная авторизация. Их исключения надо перечислить и согласовать явно; открыть весь HOME/`~/.claude` нельзя, в том числе из-за чужих транскриптов. Read-инструмент и мод-код выполняются в одном CLI-процессе: ОС не различает их по намерению. Поэтому служебное чтение требует также проверенного разграничения внутри доверенного бинарника или отдельного broker.

## Проверенные источники и варианты

Актуальность документации проверена браузером 2026-10-10. Источники ниже первичные. Код upstream `main` не считается точной ревизией встроенного кода бинарника.

**Встроенный sandbox Claude.** Он покрывает shell-команды; file-tools, hooks, MCP и helpers остаются снаружи. Он не решает наш профиль Read/Glob/Grep. Документация предлагает для общей границы изолировать сам процесс CLI. [Anthropic: sandbox scope](https://code.claude.com/docs/en/sandboxing#what-runs-outside-the-sandbox).

**Внешний Seatbelt / sandbox-runtime.** SRT оборачивает произвольный процесс; на macOS использует sandbox-exec и разрешает localhost-порт доверенного прокси. Чтение по умолчанию открыто, поэтому нужен deny всей файловой области с явными allow-исключениями; запись ограничивается allow-путями. README отдельно не обещает защиту ранее созданных hardlink на macOS. Это применимый кандидат для прототипа, не достаточное подтверждение. [Anthropic: SRT](https://github.com/anthropics/sandbox-runtime), [генератор macOS-профиля](https://github.com/anthropics/sandbox-runtime/blob/main/src/sandbox/macos-sandbox-utils.ts).

Локальные Apple man pages `sandbox-exec(1)` и `sandbox_init(3)` помечают API deprecated и предлагают App Sandbox. Наличие deprecated утилиты не означает, что её текущая kernel-изоляция отсутствует; но это ограничение стабильности интерфейса, которое нельзя скрыть. `sandbox_init` также описывает проверки при приобретении ресурса: нужно учитывать унаследованные FD и внешние brokers, не только пути.

**App Sandbox + helper.** Документация Apple описывает подписанный helper с наследованием sandbox; networking entitlement даёт класс доступа, а не список provider-доменов. Поэтому сама подпись не заменяет сетевой broker. Для установленной сторонней CLI не выбран и не проверен такой launcher/состав исключений; её не переподписывали. [Apple: helper](https://developer.apple.com/documentation/xcode/embedding-a-helper-tool-in-a-sandboxed-app), [Apple: entitlements](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html).

**Доменный broker.** Существующий CLI поддерживает HTTP(S)-proxy; SOCKS не поддерживается. Настройка proxy сама по себе не запрещает прямые соединения: это должен делать kernel-профиль. Кандидат — CONNECT только к точным provider-host:443, без wildcard, внешнего parentProxy и автоматического добавления доменов; проверять IP после DNS и запрещать локальные/private/metadata адреса. Не логировать Authorization/тела. CONNECT-контроль назначения не инспектирует TLS payload и не означает запрет передачи данных самому провайдеру. Порты/endpoint OAuth, refresh и managed-fetch должны войти в проверенную комбинацию. [Anthropic: network configuration](https://code.claude.com/docs/en/network-config).

**Штатная авторизация.** На macOS Claude использует Keychain, с файловым fallback в `.credentials.json`; изменение CLAUDE_CONFIG_DIR меняет и Keychain-entry. Значит, перенос HOME/credentials не эквивалентен прежнему входу. У native-кандидата должны сохраниться реальные HOME/configDir и доступ только к необходимым state/auth операциям; общий mach-lookup ко всем сервисам не допустим. Наш лабораторный deny-default не разрешает Keychain и не тестирует его; успех cat/nc не доказывает совместимость auth/TLS/refresh. [Anthropic: credential management](https://code.claude.com/docs/en/authentication#credential-management).

**Managed.** Настройки выше CLI; источники могут объединяться и содержать policyHelper. Документированные `/status` и doctor помогают сверке, но старые fixtures не содержат полного эффективного снимка; мы их не выдаём за такой снимок и не отключаем чужую MDM-политику. [Anthropic: managed settings](https://code.claude.com/docs/en/managed-settings), [приоритет settings](https://code.claude.com/docs/en/settings#settings-precedence).

**Container/VM.** Удалённый/гостевой процесс может видеть только собственную копию worktree; гостевое дерево можно остановить уничтожением среды, а egress пустить через host-broker. Это сильнее path-only wrapper, но не использует текущий macOS Keychain автоматически. Потребуется отдельный штатный login в гостевой среде или спроектированный credential broker; секреты туда не копируем. Пока это изменение выбранной среды/авторизации, требующее решения пользователя. [Anthropic: sandbox environments](https://code.claude.com/docs/en/sandbox-environments#virtual-machine).

## Локальная немодельная лаборатория

Окружение: **macOS 15.0.1 / 24A348, arm64, Darwin 24.0.0**, Node **24.15.0**. Установленный пакет Claude — 2.1.295; путь realpath `/opt/homebrew/lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe`, SHA-256 `0116ee2e0a513900b633d9951367f18747686478e2b462805b8c31609f047f70`, размер 239695888. Подпись сообщает Identifier `com.anthropic.claude-code`, TeamIdentifier `Q6L2SF6YDW`; это идентификация бинарника, не attestation изоляции. Статическая проверка нашла имена builtin в бинарнике; отдельно выполнена только немодельная --help-проба ниже.

Воспроизводимый стенд: `tests/isolation/macos-seatbelt.probe.ts`. Запуск:

```sh
MACOS_ISOLATION_PROBE=1 sh scripts/with-node.sh node --experimental-transform-types tests/isolation/macos-seatbelt.probe.ts
```

Он не входит в обычный CI и не вызывает Claude. Сам создаёт `os.tmpdir()/vs-seatbelt-*`, свои файлы/symlink/hardlink и два HTTP-сервера на 127.0.0.1. Команды `/bin/cat`, `/usr/bin/touch`, `/bin/sh`, `/usr/bin/nc` запускаются **через производственный createProcessRunner**, а тот запускает `/usr/bin/sandbox-exec` с массивом аргументов. Shell применяется только для фиксированной лабораторной операции с путём отдельным аргументом. Прототип не импортируется production adapter и не выдаёт AccessVerification.

В sandbox Codex локальный listen получил EPERM; для независимой проверки запрошено техническое расширение прав. Вне него первая версия SBPL получила exit 65: macOS принимает `remote ip "localhost:<port>"`, а не `127.0.0.1:<port>`. После исправления файловые пробы прошли, но curl не стартовал полноценно с минимальными системными разрешениями; это не считалось сетевой изоляцией. Нужное свойство проверено простым nc с положительным контролем второго сервера вне исследуемого SBPL, без расширения Mach-разрешений ради curl.

Заключительный прогон: **exit 0, observations-complete**, 14 наблюдений. Артефакты `os.tmpdir()/vs-seatbelt-evidence-6K9XqT`; просмотренные копии `tests/fixtures/isolation/macos-15-seatbelt/`. Это отдельные лабораторные артефакты, не Claude real-redacted fixtures и не positive evidence. Hash в metadata относится к обезличенному SBPL; текущий port динамический.

| Наблюдение | Результат |
|---|---|
| Прямое чтение worktree | разрешено, control получен |
| Прямое чтение outside и symlink из worktree туда | отказ, exit 1 |
| Создание файла runtime | разрешено, exit 0 |
| Запись worktree / outside / Git HEAD / runtime symlink наружу | отказ, exit 1 |
| Дочерний sh → cat outside | отказ; выбранная fs-граница наследуется |
| Hardlink outside → worktree | **внешнее содержимое прочитано**, exit 0 |
| Hardlink outside → runtime | **внешний файл изменён на CHANGED**, exit 0 |
| Оба localhost endpoint без SBPL / разрешённый port с SBPL | ответ control получен |
| Другой port с SBPL | отказ, exit 1; сервер не получил дополнительного запроса |

Именно hardlink делает этот простой кандидат **непригодным** для verified. Предварительный `nlink`-скан — полезный отказ, но сам по себе не устраняет гонку внешнего процесса/смену алиасов. Для продолжения native-варианта нужен стабильный снимок файлов с независимыми inode/томом, запрет последующих link/move/mount обходов и анализ runtime/auth-исключений. Простое копирование в другую папку не даёт такой гарантии. Защита против другого произвольного процесса того же пользователя — отдельная модель угроз; её нельзя молча вывести из нашего теста.

В обычный ProcessRunner-тест добавлена безопасная регрессия detached: только свой ребёнок, отдельная группа, ограниченная жизнь 1 с, собственный marker и самостоятельный exit. Запись происходит после done родителя. Тест не убивает PID по поиску и не оставляет бесконечно живого процесса. Он документирует конкретный предел, а не исправляет его.

Отдельная лаборатория `tests/isolation/macos-auth.probe.ts` проверила старт именно установленного CLI через ProcessRunner/sandbox-exec. Использованы **штатные HOME/configDir/env**, сеть и прямые записи вне собственного tmp запрещены; чтение разрешено только системному runtime, точному бинарнику, `.claude.json`, `.credentials.json` и собственному стенду. `.claude/projects` не разрешён; чужие транскрипты не читались. В отличие от строгой cat/nc-лаборатории здесь прочие операции, включая Mach IPC, открыты намеренно только для проверки совместимости — это не production-профиль.

Команда: `MACOS_AUTH_PROBE=1 sh scripts/with-node.sh node --experimental-transform-types tests/isolation/macos-auth.probe.ts`, с техническим расширением прав. Скрипт наблюдений завершился exit 0, но **CLI --help вернула exit 1**, signal null, stdout 0 байт, stderr 4983 байта. По gate **auth status не запускался**, авторизация осталась неподтверждённой в этой комбинации. Не превращать завершение скрипта в успех проверки CLI. Raw stdout/stderr не записывались (auth-ответ потенциально содержит account/email); сохранены только коды/размеры/boolean и обезличенный профиль. Конкретный startup-error из скрытого stderr не классифицирован, поэтому не делается вывод о принципиальной несовместимости Keychain/Seatbelt. Подтверждено лишь: кандидат не проходит gate старта CLI; какие разрешения или условия ему нужны, этот вывод не устанавливает. Артефакт: `tests/fixtures/isolation/macos-15-auth/auth-compatibility.json`; временный оригинал `os.tmpdir()/vs-auth-evidence-Ob03qa/`. Повторов CLI и --version в этом исследовании не было, модель не вызывалась, секреты не копировались, штатное состояние не переносилось.

## Builtin plugins: происхождение и исполнение

В `init` всех четырёх реальных потоков указаны `path: builtin`, `source: <name>@builtin`. Те же имена найдены в подписанном установленном бинарнике, поэтому это не свидетельство загрузки plugin-приманки стенда.

Официальная таблица описывает `cc-plugin-agents-md` как загрузчик AGENTS.md, а `cc-plugin-plugin-authoring` как skill без mod-кода. Builtin-компоненты не выключаются safe-mode/bare/disableAllHooks; их можно отдельно отключать через управление plugins. [Anthropic: builtin mods](https://code.claude.com/docs/en/plugins/mods/overview#mods-built-into-claude-code).

Публичный исходник agents-md регистрирует session.start, prompt.context и Read-handlers; может искать instruction-files среди предков. Это возможное исполнение внутри CLI, не обязательно отдельный процесс. Число вызовов tool_started не охватывает эти handlers. Исходник upstream не доказывает, что конкретный handler загрузил файл в наших четырёх сессиях. [Manifest](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/.claude-plugin/plugin.json), [handlers](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/hooks/register.ts).

`init.plugins` подтверждает регистрацию. Пустые skills/slash_commands и отсутствие вызова Skill не доказывают отсутствие чтения/исполнения agents-md. Для plugin-authoring документирован skill без mod-кода, но его фактическая загрузка в prompt также не подтверждена. **Проверка `init.plugins === []` сохранена**. В argv и постоянные пользовательские enabledPlugins изменения не вносились. Возможное per-run отключение через settings требует проверки effective managed-приоритета и поведения именно 2.1.295; не добавляем blacklist двух имён как обещание отсутствия всех builtin.

## Решение и необходимые условия AccessVerifier

Минимальное решение для **всех** обязательных границ в текущей комбинации пока не обосновано. Production остаётся fail-closed. Обновлена лишь причина отказа: flags не подтверждают отключение builtin. Файловый и сетевой backend, положительный AccessVerifier и фиктивное evidence не добавлены.

Доверенный verifier должен подтверждать **тот launcher, который реально используется для запуска**, а не отдельную удачную команду. Текущий callback возвращает status/evidence, после него adapter вызывает обычный runner.start; сами строки evidence этот spawn не изолируют. Будущий контракт должен связать проверку с неизменным launch-plan/изоляционным runner и ресурсами broker. В комбинацию входят ОС/backend, binary hash/signature/version, эффективная конфигурация/её изменение, auth-метод без секретов, canonical корни и inode-политика, системные исключения, argv/env, proxy/endpoint-политика, принадлежность процессов и срок применимости проверки. Ошибка/смена любого обязательного элемента запрещает запуск. Успех модели или снимок нескольких контролей не заменяет эти условия.

Нужно выбрать дальнейший архитектурный путь, не ослабляя SPEC:

1. **Native backend со штатным Keychain:** продолжить отдельный прототип launcher + доменный broker + стабильная файловая область + аудит managed/builtin и topology процессов. HOME не меняется, CLI не переподписывается без отдельного решения. Рекомендован как исследовательский следующий шаг при обязательности текущей авторизации; готовности backend сейчас нет. Потребуется явно определить допустимые runtime/auth чтения/записи и поддержку deprecated Seatbelt либо подписанного helper.
2. **VM/изолированный worker:** расширить 0C на guest backend, собственный Git и контролируемый egress, с **новым штатным входом пользователя в гостевой среде**. Текущий Keychain не переносится. Даёт другую проверяемую комбинацию и требует согласования смены среды/авторизации; не объявляется готовым без реализации и проверки.

Если ни этот объём native-backend, ни другой штатный вход не подходят, практическое решение — оставить реального агента недоступным. Разрешение на дополнительные модельные вызовы эту техническую блокировку не снимает.
