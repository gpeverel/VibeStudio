## Наблюдение (прежняя среда A, до передачи)

Добавлена отдельная проба `scripts/macos-gui-probe.c` с обёрткой `scripts/macos-gui-probe.mjs`. Обёртка собирает фиксированный исходник системным clang в собственном tmp, запускает его и удаляет только свой каталог. На сборку отведено 15 с, на исполнение 3 с; превышение даёт ошибку. Дополнительные аргументы не принимаются. `npm run smoke` не менялся.

Проба вызывает `bootstrap_look_up` для двух фиксированных имён в текущем `bootstrap_port`, освобождает полученные права портов и выводит JSON. Она не создаёт окно, не регистрирует приложение, не отправляет последующие сообщения найденным службам и не изменяет sandbox/namespace/настройки. Семантика lookup описана [Apple](https://developer.apple.com/documentation/endpointsecurity/es_event_bootstrap_look_up_t); значения кодов сверены с установленным SDK `MacOSX.sdk/usr/include/servers/bootstrap.h`.

Выполнен один запуск:

```sh
sh scripts/with-node.sh node scripts/macos-gui-probe.mjs
```

Сборка с `-Wall -Wextra -Werror` прошла. Проба завершилась **exit 1**:

| Служба | Код | Значение |
|---|---|---|
| `com.apple.coreservices.launchservicesd` | 1100 | `BOOTSTRAP_NOT_PRIVILEGED`, denied |
| `com.apple.windowserver.active` | 1100 | `BOOTSTRAP_NOT_PRIVILEGED`, denied |

Это прямое наблюдение отказа доступа к указанным службам для процесса в текущей среде. Оно не равно `unknown_service` и не связано с выполнением адаптера Codex: нативная часть пробы не содержит Electron, Node, React или кода адаптера.

Ранее собственные Electron crash-report показывали `abort()` в `_RegisterApplication` при инициализации `NSApplication`/AppKit. Новый отказ согласуется с проблемой доступа при GUI-регистрации. Однако точная внутренняя ветка abort и единственная причина всех исторических падений не установлены. Для этого нужен сравнительный запуск той же сборки в штатно назначенной среде с доступом к GUI-службам.

`BrowserWindow.webPreferences.sandbox` управляет renderer, а не внешними правами запускающего исполнителя ([Electron Process Sandboxing](https://www.electronjs.org/docs/latest/tutorial/sandbox)). Отключение этого параметра не обосновано новым наблюдением; он сохранён. Успешный Electron/SQLite в режиме Node также не подтверждает GUI-регистрацию.

После подтверждённого отказа повторный smoke в этой же среде не выполнялся. Статус smoke — **blocked, не passed**. Разовое повышение недоступно (`approval_policy=never`); другой движок для обхода ограничений автоматически не запускался.

## Передача проверки

Нужен назначенный пользователем исполнитель с разрешённым GUI-доступом в той же рабочей копии. Более широкие полномочия относятся к его сессии; они не разрешают менять sandbox, HOME, авторизацию или глобальные настройки и не переносятся в адаптер VibeStudio.

Проверяемое неизвестное: проходит ли неизменённый smoke при доступных службах или остаётся отдельный дефект приложения/Electron. Один preflight указанной командой; при любом denied/error/unknown_service — остановка без smoke и без повторов. При reachable обеих служб допускается один штатный `sh scripts/with-node.sh npm run smoke` после сборки; приложение имеет таймаут 15 с. Исполнитель обязан наблюдать процесс и при отсутствии завершения к 20 с остановить только собственную группу, дать до 2 с на выход/потоки и отразить unconfirmed при отсутствии подтверждения. Повтор без новой причины не выполняется.

Нужно сохранить код выхода/сигнал, длительность, stdout проверки окна либо безопасную сводку crash-report именно собственного PID, результат cleanup. Успешный lookup сам по себе не закрывает smoke. Проба не требует модели или сети; штатный GUI-запуск может создавать собственный временный профиль и системный crash-report. Нельзя удалять чужие процессы, профили или журналы.

Эта передача не является разрешением Codex D/M. Условия D и отдельного согласия находятся в [P3-DIAGNOSTIC-RUNNER.md](P3-DIAGNOSTIC-RUNNER.md); модельная приёмка M остаётся заблокированной отсутствием production-допуска.
